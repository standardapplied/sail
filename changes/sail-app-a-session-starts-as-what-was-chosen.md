- **New session's Shell opens a new shell.** Shell (and Open a Shell) in New session always opens a new shell in its own tab, focused, instead of choosing a tab the workspace already had; Open keeps going to the workspace's sessions.
- **A key is named only while it does what it says.** The two feet, a row's Open and every button's key, after its label and in its tooltip, ask one rule: a view holds the keys while it is the first responder of a window that is key, so a sheet over the window or another window taking key status takes every hint with it. The Workspaces foot names no key with no row chosen, Return (on a row it opens) and ⌥⌘T only while the list holds the keys, and ⌘N only while a workspace can be made and the window is key; New session's foot names ↑↓ only while its rows hold the keys and ⌘M only while a mode menu shows, and its Start names ⏎ only while the panel holds them; a row's Open names ⏎ and a button its key, after its label and in its tooltip, only while that key works, and a disabled button names none; Start wears Return's ring only while the panel's rows hold the keys, never under a sheet. The files panel's "~/workspace is empty." adds "⌥⌘N makes a file." only while the tree holds the keys, and a file pane's lost save adds "⌘S to save again." only while the keys are in the pane. A button with a key keeps the key's room while the key is not named (disabled, or its window not key), so it keeps its width; a row's Open on a row not chosen has no key, keeps no room and is centred.
- **A new workspace's first Claude Code start says nothing about a missing configuration file.** A template, and a workspace leaving its person, no longer keeps Claude Code's `~/.claude/backups` without its `~/.claude.json`, which made the first session start with "Claude configuration file not found" twice. The backups (copies of that file, which holds the signed-in account) go with it on every strip.
