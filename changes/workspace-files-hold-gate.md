- **A workspace's files hold their gate, their bytes and their names.** Every sweep of the terminal host asks each files connection's workspace again, as its ticket did: a re-own, a disown or a relabel ends a connection its person may no longer enter (`forbidden`), a workspace that went or stopped ends it (`not_found`, `workspace_stopped`), an outage ends nothing. A read stats its file again after its bytes and ends with them only when that version and the byte count are the ones it began with, else it is refused with the new kind `changed` and the client reads again; its bytes are read without waiting, so a pipe swapped in mid-read ends it. A name is carried as its bytes in every files frame (Java `FileNames`, SailKit `FileName`, shown with `U+FFFD`), so a name that is not UTF-8 is listed, read, stat-ed and watched as itself and two such names never merge. A path with a `.` or `..` part, or an empty one, is refused before anything runs, and the watch resolves each path and drops one outside the home. A workspace holds at most 8 files connections and a person 16 (`limited` at the ticket, `rate_limited` when presented). A handover or a stop of the host ends every files connection saying so (`terminal_unavailable`). A watch that cannot start ends its connection saying so. Within the same unreleased `SAILPTY7`: the files frames' names are bytes, and `FileRefusal.changed` is new.
