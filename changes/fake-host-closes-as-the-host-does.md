- **SailKit's fake host ends a connection as the host does, so a drop on macOS is always seen.** `SessionFixTests.aHostThatAttachesAndDropsParksTheSessionAfterFiveTries` failed about once in a hundred Mac runs, never on Linux: the session stayed attached for 5 s after the fake host dropped it. The session's reader was blocked in `recv()` on its socket with the end of the stream already waiting there (a non-blocking peek read it), not woken: on macOS a unix socket's `shutdown()` does not always wake a thread already blocked reading the other end (a plain POSIX repro on the Mac missed up to 26 of 2000; Linux and TCP none; a `close()` woke every one), and the fake host only shut its end down, keeping the socket open, where the real host closes its channel. `FakeHost.Peer.close()` now shuts down and closes its socket, and a test holds that it is closed, not only shut down. The product is unchanged: the host ends connections with a close, a detach is answered by one, and a session's own close sets its end at once.
