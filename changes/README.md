One file per change, directly in this folder: a branch agent/<name> keeps its entry in changes/<name>.md, so a spec's branch agent/<spec-id> adds changes/<spec-id>.md, its later pull requests edit it (or add it again once a release has folded it), and a second branch of one spec has an entry file of its own. A pull request may correct another entry not yet released but adds or deletes no other (a branch of another name adds at most one), and none edits CHANGELOG.md.
The file holds the change's entry as it would read under the version heading: one or more bullets, each opening with its bold headline closed on the same line, `- **…** …` (ci/changelog refuses a bullet that does not), with LF line ends.
The release folds every file into CHANGELOG.md with `ci/changelog X.Y.Z` in the version bump's commit, on a full clone, oldest first by the commit that added each (renaming a file re-dates it).
