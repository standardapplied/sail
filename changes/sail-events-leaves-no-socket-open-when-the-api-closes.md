- **`sail events` returns with its connection closed when the API drops the stream.** When the API closed the stream mid-follow, the JDK's HTTP client closed its own connection from one of its worker threads, and could still be doing so after the client had closed, since a client's close waits for its selector thread only. So `sail events` could return with its connection to the API still open, in CLOSE_WAIT, until that thread got to it. The client now runs its work on an executor that `sail events` closes after the client, which waits for every task the client gave it.
