- **A change's entry is a file of its own, and the release folds them in.** Every pull request added its entry at the top of `CHANGELOG.md`, so each merge conflicted with every other open pull request, which then needed main merged and a full CI run again. A pull request now adds one file, `changes/<short-slug>.md`, holding its bullets as they would read under the version heading (`changes/README.md`), and never adds to `CHANGELOG.md`: `ci/check changelog`, run by bare `ci/check` and by CI's first job on every pull request, refuses one that does, naming the file to add instead (one that only removes lines, as moving entries out does, passes). The release runs `ci/changelog X.Y.Z` in the version bump's commit, which puts every file's bullets under a new `## X.Y.Z` at the top of `CHANGELOG.md`, oldest file first by the commit that added it, and removes the files; it refuses a version already there, an empty `changes/`, and a file whose first line is no bullet, before writing anything. The bump is pushed to main, never through a pull request, so the check does not meet it. The unreleased 0.75.0 entries moved to `changes/`, one file per change; a fragment, like the changelog, starts no CI lane.
