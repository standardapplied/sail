- **The server reads everything a chat with Claude Code says on the wire.** `LiveStream`, the one reader of Claude Code's stream-json, now reads, besides text and tool calls: a `control_request` `can_use_tool` as a permission request (tool, input, `display_name`, `description`, `decision_reason`, the harness's own `permission_suggestions`), as a question (`AskUserQuestion`, its questions and choices) or as a plan to approve (`ExitPlanMode`); a `control_cancel_request` as a request withdrawn; a subagent's lines (`parent_tool_use_id`, `agent_id`, `subagent_type`, `task_description`) as the subagent's own, its text included; `system/api_retry`, `compact_boundary` and `status` (with `permissionMode`); `system/init`'s model, mode, tools, commands and skills at every turn; a tool call's whole input and a result's output; and a `result`'s own turn's cost and tokens (`model_usage_since_last_result`, since `total_cost_usd` adds up over the process), its duration, an interrupted turn (`terminal_reason` `aborted_streaming` or `aborted_tools`), a turn Claude Code began itself (`origin` `task-notification`) and what came of the login. A line of a type it does not read is kept as `other`, naming its type, and is never fatal. The live room member reads exactly as before. No route serves any of it yet.
- **The server can write a chat's side of the protocol.** A message with images before its text; a `control_response` that allows a call (with the input to run, its own or a changed one), allows it always (handing back Claude Code's own suggestions), answers a question, or denies with the person's words; and the `interrupt` and `set_permission_mode` requests. Each is the line Claude Code 2.1.332 was recorded acting on.
- **Claude Code has a chat launch and chat modes.** `claude --print --input-format stream-json --output-format stream-json --verbose --include-partial-messages --settings ~/.sail/claude-live.json --permission-prompt-tool stdio`, with the model, the mode and the conversation to resume, and never `--bare`; a person chooses among "Asks first" (Claude Code's own `default`, named at launch as `--permission-mode manual` so a workspace's default never overrides it), "Edits freely" and "Plans first", and a resumed chat starts in whatever mode Claude Code last said it was in. Each step maps to one harness-neutral chat item (text, a tool row of a kind with plain words and what it works on, a request and its withdrawal, a notice, a turn's end, a failure, a turn begun by the agent itself), with Claude Code's tool names mapped to kinds in its own harness class. What the agent wrote is clipped where the item is made and says so, but only what is shown after the fact (output, text): a person can never allow what they were not shown whole, so a permission request, question or plan any part of which would be clipped is refused at once, the agent told to split it into smaller steps and the person told why, and so is a request on a line past the frame ceiling. "Always allow" is offered only in plain words a person reads correctly: a rule as "this exact command: `…`" or "any command that starts with `…`", with what Claude Code was recorded letting it cover besides (behind `timeout`, `nice` or `nohup`, inside a longer line whose other commands need no asking, and for a prefix behind `xargs`), where it is kept and for whom; a folder quoted; a mode switch with what the mode grants (Edits freely deletes, moves and rewrites files in the workspace without asking) and that it stays for the rest of the chat. It is not offered at all for a suggestion Sail cannot say: one with a field Sail does not know, a compound command (`&`, `;`, a pipe, `$(…)`, a line break), a rule that runs `xargs` anywhere, a rule or folder holding a backtick, `..` or a character not drawn as itself, or sentences together longer than a card shows whole. A mode's words say only what a recording shows it doing. A call is drawn by its kind only when its input holds nothing but what that card draws; any other field and its whole input is shown, so nothing a person allows rides along unseen. A subagent's request names the subagent asking. A request that cannot be read whole is refused at once instead of leaving the turn waiting.
