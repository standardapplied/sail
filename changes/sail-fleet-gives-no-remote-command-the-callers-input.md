- **The fleet gives no remote command its caller's input, bounds every check, and turns off Ubuntu's daily upgrade on its boxes.** The 0.76.0 serial gate was started with an open pipe as its input, and `sudo incus launch ubuntu-24.04 zm --storage twin` waited 50 minutes for that pipe to end: ssh hands a remote command its own input, and `incus launch` reads its input to the end when it is no terminal (a group run passed, because bash gives a background job `/dev/null`). `ci/fleet` now reads `/dev/null` from its first line, so a run behaves the same whatever its input is (a terminal, a pipe nobody closes, a closed descriptor); a here-string or pipe a check gives a command on purpose still arrives whole, in a parallel group too, and `ci/fleet ssh`, a person's own command, still passes theirs on. Every check runs in a process group of its own and ends with all it started at its limit, `FLEET_CHECK_LIMIT`, 1200 s by default (the longest passing check that is not a declared wait took 791 s); it then FAILs as `FAIL NAME (did not end within N s; see LOG)` and the run goes on. Checks that wait longer by design name their own limit: the four Incus installs of init and join 3600 s (one passing run's Zabbly download took 2548 s), the loop's waits for awaiting_merge 2100 s and 3000 s, its question 1500 s and its idle-stop poll 2700 s. A run on 26 Nov failed two checks because Ubuntu's `apt-daily-upgrade.timer` upgraded libc6 on eng mid-run and needrestart restarted `sail-api`, which starts every workspace's idle clock again: `ci/fleet install` now disables and stops `apt-daily.timer` and `apt-daily-upgrade.timer` on every box (letting an upgrade already running finish) before Sail is installed, as it does on the rebuilt main, and a check says both are inactive and disabled; the idle-stop check reads `sail-api`'s start and FAILs naming a restart during the idle period it times. The loop's two rows that write a spec read it back and FAIL when its stored body is empty, so a body that never reached eng fails there and not at the rows its agent's work fails later. `CiFleetTest` proves each against stand-ins for `gcloud` and `ssh`. No behaviour of Sail changes.
