- **Every module's tests close what they open, ask DNS nothing, and pass on one CPU.** `ClosesWhatItOpens` is now registered once, in sail-core's test resources, and the test-jar carries it to sail-harness and sail-infra, so every class of every module ends with the descriptors it began with; `Databases` moved to sail-core's test-jar beside it. sail-core's and sail-harness's tests close their stores, pipes and connections, end the hosts they start, close a handoff's masters, and close all three streams of every process they start (`Child.run`, or no pipe at all). The native fleet ends main's sshd and reads its output to the end before it returns from `close`, so the fleet test no longer leaves that pipe for the JDK's reaper to close after the class has ended (main's CI saw it once). Every test JVM, unit or integration and however it is started, resolves names through `KnownHosts`, a resolver sail-core's test resources register with the JDK: a fixed table of the names tests use, and every other name unknown, so no test asks DNS and none rests on a resolver; production keeps the system's resolver and is unchanged. `LivenessAuditTest` settles on a platform thread, so SQLite's busy wait no longer holds the only carrier of a one-CPU JVM, and releases its upload only once the settle has begun its turn, so every run proves an upload during settlement. The largest descriptor count at a class boundary fell from 81-124 to 39 in sail-core and from 43-50 to 41 in sail-harness. No behaviour of Sail changes.
