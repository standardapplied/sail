- **Every agent has exactly two ways in: its own sign-in inside the session, or one stored key.** Claude Code takes one kind of key, `api-key`, as Codex does, and `sail agent login`'s `--kind` help says so.
- **Wire: the agents route says each agent's own sign-in, and whether the workspace holds it.** `GET /v1/projects/{p}/workspaces/{w}/agents` gives each offer that starts inside (`inside` true) its own sign-in, `sign_in`, `{name, how, signed_in}`: `name` is "Your Claude account" or "Your ChatGPT account"; `how` is the sentence a client says, "Claude Code asks you to sign in with your Claude account when it starts, once in each workspace." (Codex CLI's adds "Choose “Sign in with Device Code” there, after turning it on in your ChatGPT security settings."); `signed_in` is true when the file the agent keeps its sign-in in (`~/.claude/.credentials.json`, never `~/.claude.json`; `~/.codex/auth.json`) is a regular file, or a link to one, there and not empty in the workspace. It is stat-ed by one `incus exec` as the dev user, never opened, and said only for a running workspace whose read answered within five seconds; a stopped workspace is not started to read it.
- **A stored thing is a key, in Sail's words.** A value or name the store refuses says what it is, a key or a git token, where it said "a login's value": "A key is one line: paste only the key.", "A key is empty: paste the key.", "A key is at most 16 KiB.", "A key is printable ASCII with no space, quote, backslash, $ or backtick.", "A key's name is 1 to 32 lowercase letters, digits and hyphens, …"; a git token's, from `sail git login` or `PUT /v1/logins/git/{host}`, "A git token is one line: paste only the git token." and the rest. Replacing, choosing or removing a key says "An agent session already running keeps the key it started with until it ends; no workspace keeps any of it."
