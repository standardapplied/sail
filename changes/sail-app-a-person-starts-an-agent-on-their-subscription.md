- **Every agent has exactly two ways in: its own sign-in inside the session, or one stored key.** Claude Code's GLM Coding Plan key kind is gone, so Claude Code takes one kind, `api-key`, as Codex does: `sail agent login claude-code --kind glm` and `PUT /v1/logins/claude-code/{name}` with `kind` `glm` are refused, "Claude Code takes no login of kind 'glm'; it takes api-key.", and `--kind`'s help says so. The database schema stays v1005, which no release has shipped: a run's `login_kind` now takes only `api-key`. A run on a stored key records the dollars its harness reported, as every key is its harness's own vendor's. `ANTHROPIC_AUTH_TOKEN` is still set empty on Claude Code's launches, since it outranks the API key.
- **Wire: the agents route says each agent's own sign-in, and whether the workspace holds it.** `GET /v1/projects/{p}/workspaces/{w}/agents` gives each offer that starts inside a `sign_in` object, `{name, how, signed_in}`, in place of the remedy it was: `name` is "Your Claude account" or "Your ChatGPT account"; `how` is the sentence a client says, "Claude Code asks you to sign in with your Claude account when it starts, once in each workspace." (Codex CLI's adds "Choose “Sign in with Device Code” there, after turning it on in your ChatGPT security settings."); `signed_in` is true when the file the agent keeps its sign-in in (`~/.claude/.credentials.json`, never `~/.claude.json`; `~/.codex/auth.json`) is there and not empty in the workspace. It is stat-ed by one `incus exec` as the dev user, never opened, and said only for a running workspace whose read answered within five seconds; a stopped workspace is not started to read it. A remedy's command no longer runs `elsewhere`: nothing names one now, so `remedy_runners` is `sail`, `client` and `program`.
- **A stored thing is a key, in Sail's words.** A value or name the store refuses says "key": "A key is one line: paste only the key.", "A key is empty: paste the key.", "A key is at most 16 KiB.", "A key is printable ASCII with no space, quote, backslash, $ or backtick.", "A key's name is 1 to 32 lowercase letters, digits and hyphens, …".
- **The app starts an agent on its own sign-in or on a stored key, and says which.** In the New Session panel the chosen agent shows Mode in every state, then Sign in, a pop-up with the agent's own sign-in ("Your Claude account", "Your ChatGPT account"), the person's default key (`API key “default”`) and, after a separator, Store a Key. With nothing chosen the sign-in is chosen, a key stored or not; the choice is remembered for each agent on this Mac, and storing a key chooses it. The primary is Start and Sign In when the sign-in is chosen and the workspace is not known to hold it, else Start; the sign-in's sentence is said only then. The row's trailing text says the sign-in's name or the key. ⇥ reaches Sign in; Space or ↑ ↓ open it. Every word of a sign-in and a key is the server's, so an agent the app has never heard of is drawn from its declaration. The refusal "No Claude Code login stored…", the Store a Claude Code Login link and "Or start it and sign in inside…" are gone. The row menu's New Claude Code Session starts in the remembered mode and way, and opens the panel when a key chosen is gone.
- **Wire: `login_refusal` leaves `GET …/workspaces/{w}/agents`.** No default key is no longer a refusal there: the offer has no `login`, and its own sign-in is the way in. A start on a key with none stored is still refused by the terminal door (`login_not_stored`). The route reads the person's keys' rows, never a value.
- **⌘-click opens a web address in a terminal.** With ⌘ held, a program's own link (OSC 8) and an `http`/`https` address in the text are underlined across every row the line wraps over, with the pointing hand, and a ⌘-click opens the whole address in the browser; a workspace terminal's paths open as before.
- **Words: a stored thing is a key.** The store sheet is "Store a Claude Code key", its line "Stored Claude Code key “default”.", and the user menu's Logins is Keys.
