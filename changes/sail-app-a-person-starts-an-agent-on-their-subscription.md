- **Every agent has exactly two ways in: its own sign-in inside the session, or one stored key.** Claude Code takes one kind of key, `api-key`, as Codex does, and `sail agent login`'s `--kind` help says so.
- **Wire: the agents route says each agent's own sign-in, and whether the workspace holds it.** `GET /v1/projects/{p}/workspaces/{w}/agents` gives each offer that starts inside (`inside` true) its own sign-in, `sign_in`, `{name, how, signed_in}`: `name` is "Your Claude account" or "Your ChatGPT account"; `how` is the sentence a client says, "Claude Code asks you to sign in with your Claude account when it starts, once in each workspace." (Codex CLI's adds "Choose “Sign in with Device Code” there, after turning it on in your ChatGPT security settings."); `signed_in` is true when the file the agent keeps its sign-in in (`~/.claude/.credentials.json`, never `~/.claude.json`; `~/.codex/auth.json`) is a regular file, or a link to one, there and not empty in the workspace. It is stat-ed by one `incus exec` as the dev user, never opened, and said only for a running workspace whose read answered within five seconds; a stopped workspace is not started to read it.
- **A stored thing is a key, in Sail's words.** A value or name the store refuses says what it is, a key or a git token, where it said "a login's value": "A key is one line: paste only the key.", "A key is empty: paste the key.", "A key is at most 16 KiB.", "A key is printable ASCII with no space, quote, backslash, $ or backtick.", "A key's name is 1 to 32 lowercase letters, digits and hyphens, …"; a git token's, from `sail git login` or `PUT /v1/logins/git/{host}`, "A git token is one line: paste only the git token." and the rest. Replacing, choosing or removing a key says "An agent session already running keeps the key it started with until it ends; no workspace keeps any of it."
- **The app starts an agent on its own sign-in or on a stored key, and says which.** In the New Session panel the chosen agent shows Mode in every state, then Sign in, a pop-up with the agent's own sign-in ("Your Claude account", "Your ChatGPT account"), the person's default key (`API key “default”`) and, after a separator, Store a Key. With nothing chosen the sign-in is chosen, a key stored or not; the choice is remembered for each agent on this Mac, and storing a key chooses it: a key stored beside the default the person already had is made the default (`POST /v1/logins/{harness}/{name}:use`), so the panel, its row and VoiceOver say the key Start takes. The primary is Start and Sign In when the sign-in is chosen and the workspace is not known to hold it, else Start; the sign-in's sentence is said only then. The row's trailing text says the sign-in's name or the key. ⇥ reaches Sign in; Space or ↑ ↓ open it. Every word of a sign-in and a key is the server's, so an agent the app has never heard of is drawn from its declaration. The refusal "No Claude Code login stored…" and Start and Sign In There are gone. The row menu's New Claude Code Session starts in the remembered mode and way, and opens the panel when a key chosen is gone.
- **Wire: `login_refusal` leaves `GET …/workspaces/{w}/agents`.** No default key is no longer a refusal there: the offer has no `login`, and its own sign-in is the way in. A start on a key with none stored is still refused by the terminal door (`login_not_stored`).
- **⌘-click opens a web address in a terminal.** With ⌘ held, a program's own link (OSC 8) to an `http` or `https` address, and such an address in the text, its scheme in any case, are underlined across every row the line wraps over, with the pointing hand, and a ⌘-click opens the whole address in the browser; a workspace terminal's paths open as before. A program's link to anything else (a file, a share, another app's scheme) is no link.
- **Words: a stored thing is a key.** The store sheet is "Store a Claude Code key", and the user menu's Logins is Keys.
