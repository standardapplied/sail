- **A command's timeout is never outlasted.** A command whose own process ended while one it left behind still held its output (`sh -c 'sleep 6 & exit 0'`) held its caller until that process ended; what is left of the timeout now bounds the wait for its output and input too, and passing it is a timeout. A command whose caller is interrupted is ended with it, so an interrupted diagnosis question leaves no `incus info` running. Whether a command took its input is read from the write's own end, never raced. A timed-out start or stop's sentence now repeats systemd's state only when it is one systemd names ("an unknown state" otherwise, since whoever runs in the instance can replace its `systemctl`), and a question with less than a millisecond of the diagnosis's budget left is not asked.
