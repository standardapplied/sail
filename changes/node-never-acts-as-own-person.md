- **A node never acts as its own person on another's workspace.** On a node, a workspace labelled for a person the node does not hold by the id its label stores, one gone from it or another person given the same handle, was decided as the node's own person's: they could open a shell in it, stop it and delete it (with force, its work included), and start one whose handle was reused. Now no door acts on it there, its own person included, until the box's pass strips it and makes it nobody's: a shell, a terminal ticket, start, stop, delete with or without force, what can start and an agent start are each refused before Incus is asked, `owner_gone` for a person gone ("gone is zed's workspace, and zed is no longer active here, so it is not stopped; until the box's pass leaves it nobody's.") and `not_your_workspace` for another person of the handle ("old is labelled for a person this box does not know as ada, so no terminal opens in it; …"), which also replaces "no one's workspace" for such a workspace at an agent start on main. A label with no id is said as one, "labelled for ada without the id that says which ada". Another member on the node is refused such a workspace in the same words, where before they were told it belonged to the node's person. `sail agent attach` of a spec's workspace asks the same, running or stopped, before it starts or enters it. A node offers no delete of it, not even to the box's root; once the pass has cleared its label, the node's person deletes it. The pass no longer gives up on a workspace it cannot strip after three tries until sail-api restarts: it tries again an idle period after the first failure, then at twice the wait each time, at most an hour apart, until it is reached, and each failure writes on the workspace why and when it tries next, so its doors say "the box's pass has not been able to leave it nobody's (Error: …) and tries again at …" rather than promising the next pass. Only new entries are refused: a session opened before the label stopped resolving runs on, and its opener may attach to it again, after the host's handover too, until it ends; the pass strips the files under it. On main an admin still stops and deletes a gone person's workspace, and a start there says it in the same words.
