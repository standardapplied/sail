- **A workspace's files are read through its terminal door.** `POST /v1/terminal/tickets {"action": "files", "project": ..., "workspace": ...}` issues a ticket decided exactly as an open in that workspace is (its owner or an admin, the project read first, and on a node the same check that refuses a workspace labelled for a person the node does not hold, in its own words: "..., so its files are not read"). It names a workspace only: the project's own container is refused (422 `invalid_request`, "A files ticket names a workspace of the project: ..."). It never starts one: a stopped workspace is refused `workspace_stopped` (409) with the remedy that starts it. A connection it admits serves only the files frames, for that workspace: `FilesList` answered by `FilesListing` (each entry's name, kind `file`/`folder`/`link`/`other`, a link's target kind `file`/`folder`/`other`/`missing`/`loop`, size, mtime in ns, mode; unsorted; in frames of about 512 KiB of entries; cut at 50,000 with `truncated`), `FilesStat` by `FilesEntry`, `FilesRead` by `FilesData` frames of 256 KiB, the last at the file's end saying so (one read takes at most 20 MiB), `FilesCancel`, and `FilesWatch`, which replaces the connection's watch set, each path from the version the client holds of it, answered by `FilesChanged` and a `FilesTick` each second. A request is refused with `FilesRefused(id, kind, sentence)`: `not_found`, `not_permitted`, `outside_home`, `is_folder`, `not_a_folder`, `not_a_file`, `loop` or `failed`. Nothing is installed in a workspace: the host sends bash scripts with each `incus exec` as the dev user, every path on their standard input, never on a command line, each resolved and refused when it leaves `/home/dev`, a link included; the watch is one loop a connection that stats only the paths shown, every 250 ms, and ends when its input closes; listings and the watch leave out a save's temporaries (`.sail-save-*`). At most four scripts run for a connection, two of them reads, the rest waiting in the order asked. Every script and the watch end when the connection ends, however it ends, when a sweep finds its person no longer admitted, and when the workspace is stopped or deleted, which tells it the stop's own sentence (`Err`, then the connection closes); a script that fails because the workspace stopped or went ends the connection saying so (`workspace_stopped`, `not_found`). A stop or delete now ends a workspace's terminals and its files connections in one frame to the host (`YieldWorkspace`), so a session opened as the list was read can no longer outlive it. Measured on a GCP e2-standard-4 runner in a real workspace: an `incus exec` costs about 60 ms, listing 5,000 entries 112 ms at p95 idle and 198 ms with the workspace's CPUs saturated, the first 256 KiB of a file 78 ms and 126 ms. SailKit's `SailTerminalWire` has the frames, `TicketAction.files`, `TicketRefusal.stopped`, `FileKind`, `FileRefusal`, and `ErrorCode.workspaceStopped`. **Breaking (terminal wire): `SAILPTY7`.** An app and a runner of this release speak only to each other; one of 0.74 is said as another version of Sail.
