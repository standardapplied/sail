- **A connection's writes are applied in the order they were asked.** Each request ran on a thread of its own and took the workspace's lock in whatever order its thread reached it, so a folder removed right after a file was moved into it could be removed first. Each write now takes a turn when it is asked and passes it on once it holds the lock or ends, however it ends; writes on different connections are ordered by the lock, a later write waits for a save still receiving its bytes (at most the upload's idle limit), and reads take no turn. A request's id is free again the moment its last answer is sent, so a client may ask again with it at once.
