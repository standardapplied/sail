- **The app lane says a window server that stopped answering, and stops there.** A suite whose 240 s alarm ends it on macOS has any test process that outlived the alarm sampled (for at most 30 s) into the test logs and ended; then `clients/SailApp/ci/window-server` asks whether the window server answers a new process within 20 s, and says how long an answer took. When it does not, the lane says so with the window server's pid, start time, any report of it and its last five minutes of log (kept as `window-server.log`), runs no later suite and fails at once, and the drive opens no run, instead of each waiting on it until its own timeout (a runner whose window server went silent hung every later windowed suite and then the drive for half an hour). `ci/window-server-check` proves the ask on stand-ins each run (an answer and its time; a silence with its pid line, report and the log's last lines; a failing or missing asker), and the last line names the suites that ran and those that did not.
