- **The rules authors keep are checked by a script, in seconds.** `ci/rules` reads the clients' Swift and the modules' Java with one lexer and holds them to the rules a script can decide, each finding naming its file, line, rule and sentence; `ci/rules list` names every rule and whether it is on. On from the start: no "…" in a literal label of the app's buttons and menu items, no AppKit list or row outside `SailControls`, and a pull request's own entry. Implemented and tested, and switched on by the pull request that clears each, since `ci/rules check` fails a rule not yet on that finds nothing: inline comments, sleeps in Swift tests, design tokens, shared components, and the caps on a function's lines, parameters and nesting and on a file's lines.
- **A pull request adds or edits its own entry, `changes/<spec-id>.md`, and adds no other.** On its spec's branch `agent/<spec-id>`, `ci/changelog check` refuses a change that neither adds nor edits that file, or adds another; editing another entry not yet released stays allowed. A base that names no commit is refused, never held.
- **Every record a `--json` verb prints is held to its reflection entry by a unit test**, read from the JSON probe and its components' declared types, so a missing entry fails on Linux before the native binary does.
