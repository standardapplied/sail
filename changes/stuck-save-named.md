- **A stuck save is found in its workspace, and named with the way out.** A save whose process outlived its end was remembered only in the terminal host's memory, so a host restart, or a lock made anew after a workspace's last connection, forgot it. Before a lock's first write starts its script, and with every other write waiting for the answer, the workspace is now asked whether any process holds a file of Sail's exact temporary shape older than the save bound, leaving out the temporaries of the saves this host runs; so a save paused mid-body is never taken for a stuck one. A workspace that cannot be asked refuses the write. The refusal names the temporary: "a process there still holds <path>; when it ends, or once that file is removed, writes resume". Removing it is safe, since the stuck save's rename then fails on a missing source; a holder probe that cannot run counts as held.
