- **The app's drive keeps to its own account and its own folder, and puts back what it shares.** `ci/drive` ended every process on the Mac whose command line held `_pty-host --local`, so on a Mac shared with a person it reached for their terminal host. It now looks only at this account's processes (`pgrep -U`) and ends only what its own runs started, by their pids: the drives writing into its output folder, the terminal hosts Sail apps start from Application Support (before the runs that need none, and when it ends), and the feeder of the third run's attach client. It does not run while this account already has such a host, since that host's terminals would end with it. The drive build keeps Sail's own identifier, which its signed runs need (the App ID, the Keychain access group, passkeys), so it shares Sail's settings: `ci/drive` saves this account's settings (or that there were none) to a file of the account's own, `~/Library/Application Support/Sail/drive-saved-settings.plist` (mode 600), before the runs, puts them back exactly as soon as the drive app has gone, and removes the file only once they are back. It does not run when they cannot be saved, nor while a drive that did not end (killed, or the Mac lost power) has left that file: it names the file and the command that puts the settings back. The save is written whole (renamed into place), with the pid of the run that wrote it beside it: while that `ci/drive` of the account still runs, it is named instead and no command is given. `ci/test-suites` and the drive's `kill` step look only at this account's processes, and the third run's step ends only its own client. The drive's flood files, colour asker and flood pacer, made at fixed paths in `/tmp`, are made in the run's private folder, which `ci/drive` hands over as `SAIL_DRIVE_PRIVATE` (the drive refuses to start without it, and scripts name it as `{private}`) and removes when it ends, so two runs on one Mac never share a file. `ci/drive-check`, run by `ci/test-suites`, proves on stand-ins that another account's host lets the drive go on; that a half-written save neither stops it nor counts; that this account's own host, settings it cannot save, a save left behind and a `ci/drive` still running beside its save stop it before anything starts; and that a run that ends puts the settings back and removes its save, keeps the save when they cannot be put back, and says when it is gone; the app lane proves after the drive that the settings are as they were, no feeder is left and a second `ci/drive` on the same account starts.
