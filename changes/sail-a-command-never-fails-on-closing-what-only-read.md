- **A command that did its work no longer exits 1 on closing what it only read.** On a node, a dispatch that did all of its work (workspace, claim, branch, the agent's and the watcher's units) could still exit 1 with "Closing the sync health source failed": the connection its once-a-second sync check reads through was closed while that check was still inside a read. The close now waits for the check, and should closing that read-only connection ever fail, it is a warning naming its cause and the command keeps the exit its work earned. `agent stop` shares the fix.
- **A failure line says why.** Any error Sail prints that wraps a cause now names that cause on the same line, through every wrapper that names no fix ("Closing the sync health source failed: Session is acquired by 1 clients"), where before only API failures did and everything else printed the wrapper's words alone.
- **A database connection never closes under a statement another thread is running on it.** Closing waits for a statement or transaction in flight on another thread to end, and a call that comes after the close is refused with "Database is closed" instead of running on the freed connection. sail-api's telemetry and retention sweepers now wait for a sweep in flight when sail-api stops, before the database closes.
