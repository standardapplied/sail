- **A pull request's checks measure it from the merge they checked out.** `ci/check base` prints where a pull request left main: the first parent of the merge GitHub checked out. It refuses a HEAD that is no merge, and tells a shallow clone to fetch its history. Both workflows compute it once. The rules and entry check (`ci/check rules`), the lanes a change runs (`ci/changes`) and the PMD exclusions check (`ci/check unit sail-infra BASE`, which now runs `ci/exclusions` before installing anything) all take it as their base. The first two measured from the event's base sha, which could be older than the merge, so what main had gained since counted as the branch's own: sail#551 went red on another pull request's entry.
