- **The app speaks chat to the server.** SailKit opens a chat, sends a message, reads the log after a seq, answers a request (allow, always allow, deny with the person's words, or a question's answers), stops a turn, sets the chat's mode and ends the chat, and reads and keeps the person's How you work preference (`/v1/me/preferences`), each call through the one check that turns an ended sign-in into the welcome. Nothing is drawn yet.
- **Every item of a chat is read whole.** Each type the server logs, and each kind of a tool call's detail, is a Swift case holding every field; a known type missing a field fails the page naming the item's seq; a type, detail, tool kind or change kind this app does not know is kept by its name, so a newer server never stops a reader. The server writes one item of every type into a golden the app decodes, and the types, details, tool kinds, change kinds and decisions are pinned to the server's in order.
- **New session follows how the person works.** The agents route's forms and chat modes are read. Chat offers only the harnesses that chat, in their chat modes, the stored key always and the sign-in inside only where the harness chats so, with no Shell; Terminal is as before; Both offers each harness with the forms it opens in, the last chosen for it first, and the Shell. No harness is named in the code.
- **A chat held open never delays another call.** Long-polls go on a session of their own, each with its own connection, waiting past the server's 25-second hold.
- **A fake chat server for every later test.** `ChatDesk` holds chats seeded from the server's goldens, answers and holds reads as the server does, takes messages queued while a turn is open, and can end a chat, restart, end the sign-in or lose the chat, on a clock the test turns.
