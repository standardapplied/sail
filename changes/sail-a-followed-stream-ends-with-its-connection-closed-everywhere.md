- **`sail agent stream` and the watch's event stream end with their connection closed when the API drops them, as `sail events` does.** Both followed a stream on a JDK HTTP client whose close waits only for its selector thread, while the worker thread that saw the drop could still be closing the connection. So `sail agent stream` could return, and a watch could close its stream and subscribe again, with the old connection still open in CLOSE_WAIT. All three now follow their stream on one `FollowingClient`. It runs the client's work on an executor that it closes after the client, so its close waits for every task the client ran. A watch that subscribes again leaves no thread of the old stream behind.
