- **Every sail-infra test class closes what it opens, and a JUnit extension holds it to that.** `ClosesWhatItOpens`, registered for every sail-infra class, lists the fork's descriptors before each class and fails the class after its `@AfterAll` if one it did not start with is still open, naming each by number and target (Linux, where `/proc/self/fd` names targets). The JVM's own are not counted: the class path's jars and the kernel's random sources by target, and NIO's pre-close socket and the virtual-thread pollers by loading the two JDK classes that open them before the first listing. A class that speaks HTTP makes one client and closes it in `@AfterAll`, a test's databases close when it ends, servers built in a test are started so the JDK releases their sockets, and streams, listings and a child's pipes are closed by the test that opened them. The largest descriptor count at a class boundary fell from hundreds (1053, 780 and 890 over three runs of main) to tens.
- **Sail closes what it opens.** An HTTP client used often is held by its owner and closed with it: an event publisher's (closed by the CLI command, the sync round's operations, main's sync session or the commit announcer that opened it), each webhook notifier's and the Slack client's (closed when the API's subscriptions close); one used rarely, the release fetcher's and a command's one lifecycle event, lives for its one request. The event stream and `sail events` close their clients; a session client the host turns away closes its socket on every failure; and a terminal host waits for the upload removals its sessions started before it closes. Every process Sail starts has its three streams closed by whoever started it, rather than by the JDK once the process has exited: a process that outlives Sail (the detached watcher, the browser opener, the tunnel's `ssh`) is given no pipe it does not read, an agent's handle closes its input once its output ends, a log tail, a file script and an upload copy close their pipes once done, and a failed sync-channel close, a line consumer that throws and a log stream whose client has gone still end their process. The API no longer leaks a socket each time it fails to bind its private address while another process holds it (once per retry, the backoff growing from 1 s to a minute, for as long as the address is held).
