- **A workspace's write lock goes with the save that held it past the last connection.** A save answers before it lets go of the workspace's write lock, so a client could close its last connection on the answer while the save still held the lock; the lock was dropped only as the last connection went, and kept for good if a save held it then. What a workspace's connections share, its write lock and its changes runs, now goes by one rule: once no connection to it is left and each is idle, asked as the last connection goes, as the lock's last holder lets go and as the last run ends.
