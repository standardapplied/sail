- **⌘-click a path in a workspace's terminal and the file opens at its line.** Held over `src/App.java:42`, `src/app.ts:12:5`, `src/app.ts(12,5)` or a bare `Package.swift` as compilers and searches print them, a line soft-wrapped across rows read whole, ⌘ underlines the path in the text's own ink with the pointing hand; a URL, a time, a version, the sentence's closing full stop or a line cut by the screen's edge is never one. A ⌘-click looks for it on the workspace: as written when absolute (`~/` the home), otherwise in the folder the terminal last reported and then the workspace's root, two requests at most, `..` taken from each place on its own. It opens the first file found in the tab's file pane at its line, the caret there and a 2 pt accent bar beside it, asking first if the pane holds another file's unsaved text; the file already open only moves its caret. A folder is never opened: the terminal's own card says "src is a folder.". None found, the card says where it looked: "No file at src/Gone.java in api or in dock's root.". A stopped workspace, a refused ticket or a lost connection is said there in its own words, at once when the click comes while the connection is already so, and the click is never asked again on its own; opening another file meanwhile gives the click up, so a late find never closes or questions it. Nothing is typed into the terminal and nothing runs. A ⌘-click on a path goes to the path alone: a program that tracks the mouse still gets every other click.
