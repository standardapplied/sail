- **A signal goes only to the process its wrapper recorded.** Every signal Sail sends to a process it started in a workspace with no systemd unit holding it now first checks, inside the workspace, that the process at the pid file's pid has the start its wrapper recorded beside that pid file; otherwise nothing is signalled. That covers a chat's and a live room member's interrupt and stop, the halt of one left from before a restart, a foreground session's stop, and a claim of a spec's workspace that ends a person's terminal there. A pid file outlives its process, so after a restart of the box or the workspace its pid could name another of the person's processes, which the interrupt, the stop or the claim used to signal. One script holds the check for the single interrupt or stop and for the halt alike; a check that fails or answers nothing signals nothing and removes nothing. A halt that finds a stale pid file's process gone removes the file only while it still names that process, and a terminal whose name was removed as it opened is ended by its own attach, so a claim of the workspace never leaves one running beside it.
- **A foreground session and a workspace's terminal record their start.** Their wrappers write the process's start beside its pid file (`agent.pid.start`, `~/.sail/terminal.pid.start`) before the pid, each step chained, so a record that cannot be written starts nothing. End open agent sessions and terminals before upgrading: one started by an earlier release has no start record, so a stop of it reports it stopped and removes its pid file while the agent keeps running, untracked.
