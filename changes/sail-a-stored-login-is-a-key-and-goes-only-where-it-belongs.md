- **A stored login is a key, and it goes only to the service it belongs to.** Claude Code's `token` kind (`claude setup-token`, `CLAUDE_CODE_OAUTH_TOKEN`) is gone: Anthropic's terms forbid a developer to store a Claude.ai session token, so a subscription signs in inside the harness's own session and Sail never holds it. `sail agent login claude-code --kind token` and `PUT /v1/logins/claude-code/{name}` with `kind` `token` are refused: "Claude Code takes no login of kind 'token'; it takes api-key." `api-key` is now Claude Code's one kind, as it is Codex's, so `sail agent login claude-code` stores an API key. The database schema is v1005: a run's `login_kind` takes only `api-key`, so a box is reinstalled (`ci/fleet`'s `SCHEMA_CHANGED_IN` is 0.76.0), and a v1004 database is refused at the start naming the reinstall. With no kind of a known end, the warning of a login in its last 14 days is gone: the `ending` outcome of `agent_login_outcome` and `sail spec dispatch --json`'s `login_ending`.
- **A stored key goes to its own service against the container's environment and the harness's user and project files.** A Claude Code key's lines now set its address (`ANTHROPIC_BASE_URL`: `https://api.anthropic.com`), `ANTHROPIC_UNIX_SOCKET` empty (set, it carried every request to a socket the container chose) and `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST=1`, so Claude Code ignores an address, a provider or a credential that a user, project or managed settings file names; before, a container's profile export or a settings file's `env.ANTHROPIC_BASE_URL` received the person's key. They also set empty the credentials a host hands Claude Code by file descriptor, `ANTHROPIC_CUSTOM_HEADERS`, and the Mantle, Claude Platform on AWS and Claude on Google Cloud switches beside Bedrock, Vertex and Foundry's. An interactive API-key session, whose `apiKeyHelper` that flag would ignore, sets the same variables (the one list `Harness.pinned`) in its own `--settings` `env`, which a user's or a repository's settings file cannot outrank; before, such a file's cloud switch with its skip-auth sent the session's key to that cloud's address. A Codex run on a stored key now declares Sail's OpenAI provider on its command line, as an interactive session already did, under an id each launch draws (`sail_` and twelve hex digits), so a user `config.toml`'s `openai_base_url`, `model_provider` or a `[model_providers.sail]` table (whose `model_catalog_url` received the key) no longer reaches it. Not closed here, and owned by the draft spec `sail-a-stored-login-never-enters-the-container`: a proxy with a CA file that the container's profile exports (`HTTPS_PROXY` with `NODE_EXTRA_CA_CERTS`, `CODEX_CA_CERTIFICATE` or `SSL_CERT_FILE`) reads the key in either harness; the interactive API-key session follows managed settings' `env` and a settings file's proxy and CA; Codex follows `/etc/codex/managed_config.toml` and `/etc/codex/requirements.toml`; and anything running in the container can read the harness's environment.
- **A run's login outcome says only what can happen.** With the host flag no settings file's `apiKeyHelper` or key, no key `/login` kept and no signed-in subscription stands in for a stored key, so the `refused_other` and `overridden` outcomes of `agent_login_outcome` are gone, and so is a run's `login_overridden` (the column in the v1005 schema, `GET /v1/runs` and `sail agent sessions --json`, and the run's synced row).
- **`sail agent login`, `use` and `remove` refuse in JSON under `--json`.** The refusal is the API's error envelope with its code, as `sail agent login list` already did: `--kind token --json` prints an `error` with the code `invalid_request` and the message "Claude Code takes no login of kind 'token'; it takes api-key.".
- **A Codex session Sail started on a stored key is resumed by its id.** Sail resumes it so (`codex exec resume <id>`), under a new provider id, with its earlier turns. A person's own `codex resume --last` in that workspace does not find it, because Codex looks up the last session by provider id, and each launch draws its own.
