- **A workspace's files are changed whole, and never over a newer one.** A files ticket's connection now saves, makes, moves and removes its workspace's files: `FilesWrite(id, path, base, size)` then the bytes as an upload's (`PutChunk`, `PutAck`, `PutEnd` with their SHA-256), answered `FilesWritten` with the version the file has now or `FilesConflict` with the present one (or `absent`); `FilesCreate`, `FilesMove` and `FilesRemove` are answered `FilesDone`. A save is one `incus exec` as the dev user: its temporary is made beside the file (`.sail-save-…`, never listed), its bytes copied and synced, and only then, under the workspace's write lock, which every connection to the workspace shares, the workspace's decision is asked again and the script told to go: it compares the file with the base, refuses one the dev user may not write, keeps its mode and renames over it in one call, or links a new name in one call that fails when the name was taken. So two of Sail's own saves of one base never both win, and a re-own, a disown or a relabel between a save's bytes and its end writes nothing and ends the connection in the decision's words; a decision that cannot be asked writes nothing. A move never replaces a name (`mv -nT`, decided by inode) nor goes into itself, and moves a link as a link; a remove takes a link as itself and says `partly_removed` for what it left; neither touches `/home/dev/workspace`. A save cut by its connection, a cancel or a full disk (`no_space`, with the bytes free) leaves the file and removes its own temporary; one a stopped workspace left goes at the next save in its folder. Sail makes only names that are UTF-8 with no control character (`unsafe`); a save carries at most 20 MB (`too_large`). One person holds at most 6 of a workspace's 8 files connections, so its owner and an admin never shut each other out; a watched path that resolves outside the home is told by name, and every watch refusal names its path as shown. A files decision, asked at a ticket, at every sweep and before every write, now asks Incus for the workspace's one instance (`incus query /1.0/instances/<name>`) instead of listing every instance's state and keeping one: the same answer, as fresh.
