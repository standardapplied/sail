- **CI's cache of the runner's packages installs incus on every runner that restores it.** `ci/images runner-packages fetch` resolves incus and the ZFS tools against an empty dpkg status, so the cache keeps every package they need whatever the fetching runner holds; runners of one image differ (AWS's held librados2 and librbd1, Azure's did not), and a cache fetched on one left the other unable to configure incus. `install` makes the cached files apt's only source, a flat repository, so apt takes from them only what the runner lacks, keeps a version it holds unless the package needs a newer one, and stops before dpkg runs, naming any package the files lack. The source setup is its own verb, `sources`; the verbs that change the runner run under `sudo`. `CiImagesTest` proves both over a local mirror of stand-in packages, with no network.
